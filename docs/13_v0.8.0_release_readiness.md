# v0.8.0 Portfolio Construction 1.0

> Local release-candidate verification for V7. This document does not claim
> that a commit, push, pull request, remote CI run, merge, or `v0.8.0` tag has
> been completed.

## Added

- Extensible strategy and constraint registries.
- Equal Weight, Rank Weight, and Inverse Volatility constructors.
- Deterministic Max Weight capped-proportional allocation.
- A provider-neutral HistoricalReturnService and a concrete V6-backed service.
- Holdings, Pipeline, generic CLI config, Streamlit, and Research Backtest
  integration.

## Frozen Semantics

- Holdings Top-N selects securities; Portfolio Construction weights only the
  exact selected set. It cannot add, drop, replace, substitute, or re-rank a
  candidate.
- Constructors produce constraint-satisfying weights. The Engine resolves
  registries and dependencies, then validates exact identity, weights, and
  constraints without clipping, optimization, or fallback.
- Rank Weight uses the selected-set ordinal `selection_position = 1..K`, with
  raw attractiveness `K, K-1, ..., 1`; it does not weight raw score magnitude.
- Inverse Volatility uses sample standard deviation with `ddof=1`, no hidden
  epsilon/floor, and the exact last configured number of open dates through
  `risk_cutoff`, the latest open date no later than formation.
- Max Weight is fully invested and long-only, preserves uncapped
  attractiveness ratios, and fails closed when `K * max_weight < 1`.
- No strategy or constraint may replace candidates. Portfolio Construction is
  an internal Holdings capability, not a Pipeline stage or separate Artifact.

## Compatibility

- A v0.7 Holdings config without `portfolio_construction` resolves to explicit
  Equal Weight with empty params and constraints.
- The canonical Holdings payload remains exactly `trade_date`, `ts_code`,
  `target_weight`, `score`, and `rank`; its file set and schema version remain
  unchanged.
- Existing Signal ranking, Top-N, insufficient-universe behavior, Pipeline
  stage order, generic CLI entry point, and legacy UI remain supported.
- The unchanged V6 Research Backtest validates and consumes exact Holdings
  `target_weight` with exact upstream Artifact lineage.

## Historical Return Semantics

- Security returns are canonical V6 decimal `tushare.daily.pct_chg / 100`.
- Pre-listing open dates do not count as observations. A proven full-day
  suspension with a missing daily row resolves to zero.
- Active unexplained missing data and unresolved post-delist data fail closed.
- Future returns, raw-close reconstruction, generic zero fill, candidate drop,
  and Equal Weight fallback are prohibited.

## Non-goals

This release does not implement risk parity, mean variance,
Black-Litterman, turnover constraints, sector constraints, factor constraints,
a general optimizer, or live execution.

## Release Procedure

After the user reviews and commits the V7-P3 local changes:

1. Push `feature/portfolio-construction`.
2. Open a pull request to `main`.
3. Wait for and review CI and code review.
4. Merge the pull request.
5. Verify the exact merged `main` commit locally and rerun release checks.
6. Create an annotated `v0.8.0` tag on that verified commit.
7. Push and verify the tag.

None of these commit, remote, merge, or tag operations are performed by this
local readiness task.
