## Product Positioning

V6 is a historical Research Portfolio Backtest & Evaluation capability. It is
not a live-trading system, broker simulator, OMS/EMS, order matcher, or
execution-quality simulator.

```text
Factor Research -> Modeling Panel -> ML -> Signal -> Holdings
  -> Research Backtest -> Rebalance / Cost / NAV / Benchmark / Analytics
```

Holdings remains the sole owner of ranking, Top-N selection, and target-weight
construction. Research Backtest evaluates exact validated targets.

## Key Semantics

- Schedule owner: ordered `Holdings.trade_date`; the core is
  frequency-agnostic and defines no monthly/weekly/daily behavior enum.
- Effective date: strict next trading day.
- Timing: post-close accounting. The old portfolio receives the later
  effective-date close-to-close return; the new target starts on the next open
  trading day. The first effective-day strategy return is zero from cash.
- Security return: `tushare.daily.pct_chg / 100`.
- Benchmark return: `tushare.index_daily.pct_chg / 100`; the first evaluation
  return is forced to zero.
- Missing security return: only a proven full-day suspension resolves to zero;
  unexplained, pre-listing, and unresolved post-delist cases fail closed.
- Turnover: half-L1 from drifted pre-state to target, including cash.
- Traded notional: absolute security weight changes, excluding cash.
- Cost: `traded_notional * cost_bps / 10000`.
- Net return: `(1 + gross_return) * (1 - transaction_cost) - 1`.
- Analytics use daily observations and explicit `annualization_days`, whose
  canonical default is 252.
- Benchmark code is explicit; the backend has no hidden benchmark default.
- `PipelineConfig.backtest_end` is the only evaluation-end owner.

The corresponding canonical identifiers are `holdings_dates`,
`next_trading_day`, `adjusted_close_to_close`,
`one_way_traded_notional`, and `strict_common_calendar`.

## Artifact

Schema `1.0` contains exactly:

```text
rebalances.parquet
daily_portfolio.parquet
benchmark.parquet
metrics.json
config.json
audit.json
manifest.json
```

Publication validates exact upstream Holdings lineage, stages privately,
writes the manifest last, publishes atomically, and never overwrites an
existing target. Validation checks the exact file set, SHA-256/size metadata,
schemas, semantics, lineage, and cross-file consistency. There is no
latest/mtime/glob source discovery or sibling fallback.

## Interfaces

Canonical CLI:

```powershell
python scripts/run_pipeline.py --config config/research_backtest_pipeline.example.yaml
```

No Research Backtest-specific business flags exist. The example explicitly
chooses pipeline source, Holdings Top-N 10, 10 bps cost, benchmark
`000300.SH`, and annual risk-free rate 0.0.

The Streamlit surface maps the same canonical config, calls the same Runner
once, shows metrics from `PipelineResult`, and reads NAV only from the exact
validated current-run Artifact. It has no second end date, source selector,
frequency selector, metric calculation, or NAV reconstruction.

## Compatibility

- Configurations without `research_backtest` load it disabled and retain the
  previous summary behavior.
- Existing Modeling Panel, ML, Signal, Holdings, their native Artifacts, and
  the one-way legacy root Top-N compatibility mirror remain supported.
- `src/backtest/**` legacy behavior and the separately labeled Streamlit legacy
  area are unchanged.
- Pipeline source uses exact current-run Holdings; files source uses only one
  explicit validated native Holdings Artifact.

## Release Procedure

After local V6-I changes are reviewed by the user:

1. Commit V6-I on `feature/research-backtest`.
2. Push the feature branch.
3. Open a GitHub PR to `main`.
4. Wait for and review CI and code review.
5. Merge the PR.
6. Fetch/pull and verify the exact merged `main` commit locally.
7. Rerun release verification on `main`.
8. Create annotated tag `v0.7.0` on that exact verified release commit.
9. Verify both the tag object and peeled commit.
10. Push the tag and verify the remote tag/release state.

None of these remote, merge, commit, or tag actions are performed by the V6-I
local readiness task.
