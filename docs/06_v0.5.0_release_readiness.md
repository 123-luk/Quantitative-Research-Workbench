## 固定契约

- Modeling Panel schema：`1.0`
- Artifact schema：`1.0`
- 固定 key：`trade_date`、`ts_code`
- 固定 audit columns：`entry_trade_date`、`exit_trade_date`、
  `entry_price`、`exit_price`
- 默认 label：`forward_return`
- 列顺序：key、按配置/源顺序确定的 features、audit columns、label
- Artifact 固定四文件：
  `modeling_panel.parquet`、`config.json`、`audit.json`、`manifest.json`
- source mode 只有 `files` 与 `factor_research`。前者消费两条明确 Parquet
  路径；后者只消费本次 Factor Research Result 的 PublishedOutputs。
- ML panel 来源严格唯一：显式 `ml_experiment.panel_path` 或本次 Modeling
  Panel Result 的 `panel_path`，不能同时存在，也不能同时缺失。
- Artifact no-overwrite；同一明确目录第二次写入失败且原 Artifact 保持不变。
- Builder 校验 key 唯一性、时间顺序、entry/exit 完整性以及
  `exit_price / entry_price - 1` 公式容差，不把警告冒充泄漏证明。

## E2E 分类与边界

真实执行：

- `files → Modeling Panel Artifact`：真实 `run_pipeline()`、Builder、Artifact
  Store 和 Validator。
- `Modeling Panel Artifact → ML`：真实 `run_pipeline()`，真实持久化 Parquet，
  通过 `panel_path_override` 交给真实 ML Executor，并实际训练 Ridge。
- 同一 PipelineConfig 连续两次执行、独立 run_dir/Artifact、Validator、
  no-overwrite、Builder 确定性与输入/config 不可变性。

受控 orchestration：

- `FactorResearchPublishedOutputs → Modeling Panel` 从真实 frozen
  `FactorResearchExecutionResult` 和合法 tmp Parquet 开始，真实执行 Modeling
  Panel Executor、Builder、Store 和 Validator；它不声称覆盖完整 Factor
  Research 计算。
- Builder 失败后 ML 不调用，以及 ML 边界失败后已发布 Modeling Panel
  Artifact 保留，使用 pytest monkeypatch 观测/注入下游边界。

静态契约检查：

- CLI `--help`、example `safe_load` 与 `PipelineConfig.from_dict()`、README/docs
  链接及命令参数一致性。
- 公开导入、指定文件 `compile()`、TODO/危险模式/secret-like 扫描、Git
  白名单与残留扫描。

尚未覆盖：

- 全市场或真实业务数据运行。
- 完整 Factor Research 计算与 Modeling Panel、ML 的单个全真实三阶段 E2E；
  完整 Factor Research 本身由既有 targeted tests 覆盖，本阶段只验证其
  PublishedOutputs 交接。
- 网络、远端分支分歧、远端 tag、合并后 main 状态。
- 当前 Windows 环境没有 symlink 创建权限时的四个条件测试分支。
